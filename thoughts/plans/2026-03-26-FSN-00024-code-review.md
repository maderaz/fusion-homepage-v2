# FSN-00024: Code Review — Minimize JS/React, Maximize Static Astro

## Overview

Comprehensive code review of the Fusion website to minimize JavaScript and React usage. The site is a static marketing page — most content is presentational and should be rendered as static Astro templates. React islands should only exist where true interactivity is required. Motion animations are kept as-is (deferred to a follow-up ticket).

## Current State Analysis

### React Component Inventory

| Component            | `client:*`       | Has State          | Has Effects                | Needs React?                                              |
| -------------------- | ---------------- | ------------------ | -------------------------- | --------------------------------------------------------- |
| `Nav`                | `client:load`    | Yes (menu, scroll) | Yes (scroll, overflow)     | **No** — vanilla JS suffices                              |
| `Hero`               | `client:load`    | Yes (tvmData)      | Yes (API fetch)            | **Yes** — AnimatedGroup uses Motion                       |
| `Benefits`           | `client:visible` | No                 | No                         | **Yes** — GlowingEffect + Motion icons                    |
| `HowItWorks`         | `client:visible` | No                 | No                         | **Partial** — only FusionFlow needs React                 |
| `Solutions`          | `client:visible` | No                 | No                         | **Partial** — only animated icons need React              |
| `ComparisonTable`    | `client:visible` | No                 | No                         | **Partial** — only animated icons + theme logo need React |
| `CookieBannerIsland` | `client:idle`    | Yes                | Yes (localStorage, events) | **No** — vanilla JS suffices                              |
| `PrivacyPolicyPage`  | `client:load`    | No                 | No                         | **No** — zero JS needed                                   |
| `TermsOfUsePage`     | `client:load`    | No                 | No                         | **No** — zero JS needed                                   |

### Key Issues Found

1. **Privacy Policy & Terms of Use pages load React + Motion for zero interactivity** — these are pure static HTML from static arrays, yet use `client:load`
2. **Nav** uses React for scroll detection, mobile menu toggle, and theme toggle — all achievable with vanilla JS
3. **Cookie Banner** uses React for localStorage + event handling — vanilla JS suffices
4. **Footer "Fusion Vaults" link** points to `#top` (scroll-to-top) instead of `https://app.ipor.io/fusion`
5. **Footer "Cookie Policy" link** should be removed per ticket
6. **TVM/Vaults stats** show "—" during load — should show build-time values as placeholders
7. **Solutions, HowItWorks, ComparisonTable** are mostly static layout wrapped in React just to render a few animated icons

### Key Discoveries

- `base-layout.astro:25` mounts `<Nav client:load />` on every page — converting Nav to Astro removes React from the global layout
- Privacy Policy and Terms of Use pages will ship **zero client JS** after converting Nav, CookieBanner, and the page content to Astro
- `useTheme()` hook (`src/components/use-theme.ts`) uses a `MutationObserver` on `<html>` class — the Astro components that need theme awareness can use CSS (`dark:` prefix) or the existing `dark` class directly
- Footer already uses CSS-only theme switching for logos (`block dark:hidden` / `hidden dark:block` at `footer.astro:86-92`) — same pattern works for ComparisonTable logo
- `lucide-react` icons used in Nav, CookieBanner, Solutions, ComparisonTable, PrivacyPolicyPage, TermsOfUsePage — Astro components should use inline SVGs instead
- The `components.json` (shadcn/ui config) appears unused — no shadcn components are imported
- `brand-guidelines` page no longer exists but is still referenced in Playwright tests (`console-errors.spec.ts:3`, `csp.spec.ts:3`)

## Desired End State

After this plan:

1. Privacy Policy and Terms of Use pages ship **zero client JavaScript** (only inline theme/analytics scripts)
2. Nav and Cookie Banner are vanilla JS + Astro (no React dependency in layout)
3. Solutions, HowItWorks, ComparisonTable are Astro templates with minimal React islands for animated icons only
4. Hero fetches TVM data at build time for meaningful placeholder values, updates at runtime
5. Footer links are corrected (Fusion Vaults → app link, Cookie Policy removed)
6. All Motion animations remain untouched (deferred to follow-up ticket)
7. No console errors, no runtime errors, Playwright tests pass

### Verification

- `npm run build` succeeds (includes `astro check`)
- `npm run test` — all Vitest unit tests pass
- `npm run test:visual` — all Playwright tests pass (visual + console errors + CSP)
- Manual: all pages render correctly in both light/dark mode
- Manual: mobile menu, theme toggle, cookie banner all work

## What We're NOT Doing

- Converting Motion animations to CSS/SMIL (deferred to next ticket)
- Removing GlowingEffect or animated icons (deferred)
- Removing `motion`, `react`, `react-dom`, `lucide-react` from dependencies (still needed for Hero, Benefits, FusionFlow, animated icons)
- Changing visual design or layout
- Adding new features

## Implementation Approach

Work from the outermost components inward. First fix the footer (quick wins), then convert layout-level components (Nav, CookieBanner) to remove React from the layout, then convert fully-static pages, then refactor the homepage components.

<script>

#### 3. Update Hero to accept initial props

**File**: `src/app/components/hero.tsx`
**Change**: Accept `initialTvmFormatted` and `initialVaultCount` props. Use them as the initial state instead of `null`. Still fetch at runtime to update.

```typescript
interface HeroProps {
  initialTvmFormatted?: string;
  initialVaultCount?: number;
}

export function Hero({ initialTvmFormatted, initialVaultCount }: HeroProps) {
  const [tvmData, setTvmData] = useState<TvmData | null>(
    initialTvmFormatted && initialVaultCount
      ? { tvmFormatted: initialTvmFormatted, vaultCount: initialVaultCount }
      : null,
  );

  useEffect(() => {
    fetchTvm()
      .then(setTvmData)
      .catch(() => {});
  }, []);

  // ... rest unchanged
}
```

Now the build-time HTML will contain the real TVM and vault count instead of "—", and it will update to the latest value at runtime.
